# Plan to Address PR 11 Comment by kilo-code-bot

## Problem
PR 11 optimizes the `derive_from_existing_votes` method in `app/services/elo_service.py` by fixing an N+1 query issue. However, kilo-code-bot identified a critical logic bug at line 195: "Logic bug in duplicate comparison check - ordered tuple mismatch can cause duplicates".

## Root Cause
The current duplicate check for existing `PairwiseComparison` records only queries for comparisons where `translation_a_id == v1.translation_id` and `translation_b_id == v2.translation_id`. This fails to detect existing comparisons that were stored with the reverse order (i.e., `a == v2.translation_id` and `b == v1.translation_id`), potentially creating duplicate comparisons.

## Solution
Update the duplicate check to query for existing comparisons in both possible orders using an OR condition in the filter.

### Steps:
1. Modify the existing query filter to check for both (a=v1, b=v2) and (a=v2, b=v1) combinations
2. Use SQLAlchemy's `or_` and `and_` functions to construct the compound condition
3. Ensure the fix maintains the existing filtering on query_id, user_id, and source

### Code Change:
In `app/services/elo_service.py`, around lines 182-192, replace the filter with:
```python
existing = (
    self.session.query(PairwiseComparison)
    .filter(
        PairwiseComparison.query_id == query_id,
        PairwiseComparison.user_id == uid,
        PairwiseComparison.source == "derived",
        or_(
            and_(
                PairwiseComparison.translation_a_id == v1.translation_id,
                PairwiseComparison.translation_b_id == v2.translation_id,
            ),
            and_(
                PairwiseComparison.translation_a_id == v2.translation_id,
                PairwiseComparison.translation_b_id == v1.translation_id,
            ),
        ),
    )
    .first()
)
```

### Validation:
- Run the method and verify no duplicate comparisons are created
- Check that existing functionality is preserved
- Ensure performance optimization is maintained

## Dependencies
- Add imports for `and_` and `or_` from SQLAlchemy at the top of the file: `from sqlalchemy import and_, or_`

This fix will resolve the critical issue while maintaining the performance improvements introduced in the PR.
